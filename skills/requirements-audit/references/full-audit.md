# 전체 점검 절차 (1회성)

$requirements-audit 의 "전체 점검" 모드. 과제 시작 직후 또는 제출 전에 모든 요구 문서를 한 번에 감사한다.

역할: 너는 과제 README·제공 자료·답변 기록을 감사하는 정밀 검토자다. 문서는 시점이 달라
서로 모순되는 내용이 섞여 있을 수 있다. 목표는 모순을 빠짐없이 찾아 드러내는 것이고, 해결하지 않는다.

■ 절대 규칙
- 충돌을 해결하지 않는다. 어느 쪽이 옳은지 고르지 않는다.
- 문서를 고쳐 쓰거나 요약·통합·정제하지 않는다.
- "최신이 맞을 것" 같은 추정으로 한쪽을 우선하지 않는다(제출물·형식·필수조건의 임시안만 README 쪽).
  양쪽 주장을 원문 그대로 나란히 둔다.
- 문서에 실제로 적힌 내용만 보고한다. 없는 충돌을 지어내지 않는다.
- 애매하면 보고하되, 한 번에 만드는 Q 파일 수는 SKILL.md 의 제한(영향 높음·중간 최대 7개)을 따른다.

■ 유형과 완화
- SKILL.md 의 7종과 완화 규칙을 그대로 적용한다.
  (7 미구체화 예: "로그인 지원" → 어떤 방식? / "알림 보냄" → 어떤 채널?)

■ 대상 문서
- 과제 README, 제공 파일(데이터 설명·명세·예시 포함), wiki/raw/, wiki/collab-log.md, wiki/decisions.md, wiki/PLAN.md.
- 문서가 많으면 묶음별로 처리한 뒤, 마지막에 묶음 사이의 교차 모순을 찾는 2차 통합 패스를 한 번 더 돈다.

■ 출력
- 각 건은 SKILL.md 의 Q-NNN 파일 형식으로 wiki/conflicts/ 에 쓴다(기존 항목과 중복 금지).
- 화면 요약은 영역(태그)별로 묶고 영향 높음을 맨 위로 둔다.
- 마지막에 (a) 읽은 문서 전체 목록 (b) 모순 없이 깨끗했던 영역을 덧붙인다.
